## 1. 硬件与软件架构

### 1.1 硬件链路

```
HFI-A9 IMU ──USB串口──┐
                      ├── Raspberry Pi 5 (ROS2 Jazzy)
Arduino Mega ─USB串口─┘
     │
     ├── 双路电机驱动 (PWM)
     └── 双路正交编码器
```

### 1.2 ROS2 节点与话题

| 节点 | 职责 | 发布 | 订阅 |
|---|---|---|---|
| `hfi_imu` | IMU 驱动 | `/imu/data` (~150 Hz) | — |
| `serial_bridge` | 串口协议桥 | `/wheel/encoders` (~100 Hz) | `/cmd_vel` |
| `balance_controller` | 控制器 | `/cmd_vel` | `/imu/data`, `/wheel/encoders` |

**关键点：控制周期由 IMU 回调驱动**，不用定时器。这样 D 项的差分和实际采样严格对齐，
没有定时器与传感器之间的相位误差。

```python
self.create_subscription(Imu, '/imu/data', self._imu_cb, 10)
# 所有控制计算都在 _imu_cb 里完成
```

### 1.3 姿态角的提取

IMU 给的是四元数，pitch 用标准公式提取：

```python
sinp = max(-1.0, min(1.0, 2.0 * (w * y - z * x)))
pitch = math.degrees(math.asin(sinp))
```

`max/min` 的钳位是必须的——浮点误差会让 `sinp` 略微超出 [-1, 1]，`asin` 直接抛异常。

### 1.4 PWM 的下发路径（这条链路的符号约定，后面处处要用）

控制器发布 `Twist`：

```python
def _send_pwm(self, u, sync_correction=0.0):
    cmd = Twist()
    cmd.linear.x  = u / 100.0                # 共模：前后
    cmd.angular.z = sync_correction / 100.0  # 差模：偏航
    self.cmd_pub.publish(cmd)
```

`serial_bridge` 拆成左右轮：

```python
left_pwm  = int((linear - angular) * 100)
right_pwm = int((linear + angular) * 100)
```

即 **`left = u - sync`，`right = u + sync`**。这个式子在第 5.3 节（偏航）和
第 6.5 节（摩擦补偿为什么失败）里都是关键。

### 1.5 编码器轮速的计算

左右编码器镜像安装，计数天生反向，所以右轮要取负：

```python
left_v  =  dl / dt
right_v = -dr / dt
raw_v = (left_v + right_v) / 2.0   # 共模：前进速度
turn  =  left_v - right_v          # 差模：偏航速度
```

**共模用于速度/位置环，差模用于偏航环。两者完全解耦**，
因为差模是等量反向叠加的，不改变平均前后扭矩。

## 2. 控制结构：为什么必须是串级

### 2.1 只有角度环会发生什么

最直觉的做法是：测倾角 → PID → 驱动轮子。这**确实能让车身站直**，但会出大问题。

第一轮实测 `tuneA1`（kp=70, kd=5，无速度环）的结果：

```
29 段接管，退出原因 100% 是"轮速超限"，一次都没有因为倾角摔倒
段0: 7.15s   段3: 7.76s   err 全程在 [-1.7, +2.5]° 内，17 次过零
轮速末值稳定在 ±430 ticks/s
```

**它不是倒了，是一边站着一边一路加速跑掉了。**

原因：角度环只有一个目标——让 `pitch = offset`。如果 `offset` 哪怕差 0.1°，
车身就会稳定地保持 0.1° 的倾斜，而一个持续倾斜的平衡车会**持续加速**。
角度环对此毫无察觉，因为它的误差是零。

> 这是理解整个项目的第一个关键认识：
> **车身角度稳定 ≠ 车稳定。角度环是欠驱动系统的内环，它无法约束位置和速度。**

### 2.2 四个环的分工

```
                 ┌──────────── 位置环 (ki_v) ────────────┐
                 │        ┌──── 速度环 (kp_v) ────┐      │
                 ↓        ↓                       │      │
目标位置=0 ──→ offset_trim ──→ 目标倾角 ──→ 角度环(kp/kd) ──→ u ──┬──→ 左轮 u - sync
                                              ↑                  └──→ 右轮 u + sync
                                          IMU pitch                        ↑
                                                                    偏航环 (wheel_sync_kp)
                                                                           ↑
                                                                    编码器差模轮速
```

代码里的实现（`balance_controller.py::_imu_cb`）：

```python
# 外环：速度 + 位置 → 修正目标倾角
offset_trim = kp_v * self.wheel_velocity + ki_v * self.velocity_integral
offset_trim = max(-max_offset_trim, min(max_offset_trim, offset_trim))

err = pitch - (effective_offset + offset_trim)   # ← 外环通过改目标角来指挥内环

# 内环：角度 PID
u = kp * err + ki * self.integral + kd * rate_for_control

# 偏航环：差模，独立叠加
sync_correction = wheel_sync_kp * self.turn_velocity
```

**关键理解：外环不直接输出 PWM，它输出的是"目标倾角的修正量"。**
外环通过让车身有意识地前倾/后仰，间接指挥内环去改变速度。这是串级控制的精髓。

### 2.3 一个容易被忽略的事实：`ki_v` 其实是位置环

```python
self.velocity_integral += self.wheel_velocity * dt
```

**速度的积分就是位置**。所以：

| 参数 | 名义身份 | 实际身份 |
|---|---|---|
| `kp_v` | 速度环比例 | **位置环的微分项（阻尼）** |
| `ki_v` | 速度环积分 | **位置环的比例项（刚度）** |

这个认识非常有用——它把"速度环怎么调"这个模糊问题，转化成了
"位置 PD 环的刚度和阻尼怎么配"这个标准的二阶系统问题。第 5.5 节全靠这个认识推进。

## 3. 核心理论：平衡车的非最小相位特性

**这是整个项目最重要的一个物理认识，也是最容易搞错符号的地方。**

### 3.1 反直觉的现象

问题：车正在以 v > 0 向前滚，想让它停下来，该怎么办？

**错误答案**：给轮子反向 PWM 刹车。
结果：轮子减速了，但车身因为惯性继续前冲 → 车身**更加前倾** →
角度环立刻加大前进油门去"救"它 → 车反而加速了。刹车动作被平衡环彻底抵消。

**正确答案**：先给轮子**更大的前进 PWM**。
机理：轮子冲到重心前面 → 车身被"抽"得向后仰 →
车身后仰后，角度环为了追这个后仰的重心，自己会输出反向 PWM → 车减速停下。

> **要减速，必须先加速。这就是非最小相位（non-minimum phase）系统的典型特征：
> 系统对控制输入的初始响应方向，与最终稳态响应方向相反。**

物理上的根源：这是一个**欠驱动系统**——一个执行器（轮子扭矩）要同时控制
两个自由度（车身角度 + 车体位置），只能通过牺牲一个去换另一个。

### 3.2 符号的严格推导

代码里的符号约定：`pitch` 正 = 前倾；前倾需要正向（前进）PWM 去追重心。

已知：
```python
err = pitch - (offset + trim)
u   = kp * err + ...          # kp > 0
```

推导（v > 0，想减速）：

| 步骤 | 结论 |
|---|---|
| 1. 要减速 | 需要一个**更大的前进 PWM** 的瞬态 |
| 2. u 要更正 | 因为 `u = kp·err`，所以 `err` 要更正 |
| 3. err 要更正 | 因为 `err = pitch - (offset + trim)`，所以 `(offset + trim)` 要更小 |
| 4. 目标要更小 | 所以 `trim` 要为**负** |
| 5. trim = kp_v · v，而 v > 0 | 所以 **`kp_v` 必须为负** |

### 3.3 用微分方程独立验算

设外环修正到加速度的传递为 `dv/dt = K'·trim`（K' > 0）。

> 这里 K' 的符号也要小心：`trim` 为负 → 目标角变小 → 车身最终稳定在**后仰**状态
> → 后仰的平衡车向**后**加速 → `dv/dt` 为负。所以 `dv/dt` 与 `trim` **同号**，K' > 0。

代入 `trim = kp_v·v + ki_v·x`，其中 `x = ∫v dt`：

```
dv/dt = K'·(kp_v·v + ki_v·x)
d²x/dt² - K'·kp_v·(dx/dt) - K'·ki_v·x = 0
```

特征方程：

```
s² - K'·kp_v·s - K'·ki_v = 0
```

二阶系统稳定要求所有系数为正：

```
-K'·kp_v > 0  →  kp_v < 0   ✓
-K'·ki_v > 0  →  ki_v < 0   ✓
```

**两个外环增益都必须取负值。** 两条独立路径（物理直觉 + 微分方程）结论一致。

### 3.4 历史教训

翻项目 `logs/` 目录，早期文件名是 `cmd_vel_kpv001.log`、`cmd_vel_kpv004.log`，
即 `kp_v = +0.01`、`+0.04`。**符号是反的**。

正的 `kp_v` 意味着：车向前跑 → 目标角变大 → err 变小 → 前进 PWM 减小 →
车身更前倾 → 更用力前进。这是**正反馈**，只会让跑飞更快。

这解释了为什么之前速度环怎么调都没用——不是增益大小的问题，是方向从一开始就错了。

## 4. 调参方法论：怎么摆脱瞎试

这一节是这个项目最值得写进简历的部分。**核心思想是：把调参从"试参数"变成"做测量"。**

### 4.1 工作流

```
设参数 (ros2 param set)
   → 录包 (ros2 bag record /imu/data /cmd_vel /wheel/encoders)
   → 拉回本地 (scp)
   → 离线复现控制器状态机，算指标
   → 从指标推下一组参数
```

关键是最后两步。**不靠肉眼看车，靠指标说话。**

### 4.2 离线复现状态机

录包里没有"控制器当时是否接管"这个信息，但因为知道全部参数，可以精确复现它的状态机：

```python
# 与 balance_controller 的判定逻辑严格一致
err = pitch - offset
engaged = False
for i in range(len(err)):
    if engaged:
        if abs(vel[i]) > max_wheel_v:
            segments.append((start, i, 'WHEEL'))   # 轮速保护切断
            engaged = False
        elif abs(err[i]) > max_tilt:
            segments.append((start, i, 'TILT'))    # 倾角超限，真摔了
            engaged = False
    elif abs(err[i]) < engage_below and abs(rate[i]) < engage_rate_below:
        engaged = True
        start = i
```

**`exit` 原因这一列价值极高**——它直接告诉你失败模式是什么：

- 全是 `TILT` → 角度环兜不住，调 kp/kd
- 全是 `WHEEL` → 角度环没问题，是速度/位置失控（`tuneA1` 就是这样）
- `END` → 录制结束时它还站着（最好的结果）

### 4.3 关键指标定义

| 指标 | 定义 | 诊断什么 |
|---|---|---|
| `dur` | 单段接管时长 | 总体好坏 |
| `exit` | 退出原因 | **失败模式分类** |
| `errRMS` | 角度误差均方根 | 角度环品质 |
| `velMean` | 平均轮速（**带符号**） | 单向漂移 |
| `velRMS` | 轮速均方根 | 动作剧烈程度 |
| `posSD` / `posPP` | 位置（速度积分）标准差 / 峰峰值 | 位置守得住不 |
| `surge_s` | 位置摆动周期 | 位置环阻尼 |
| `turnAvg` | 平均差模轮速 | **偏航偏置** |
| `sat%` | PWM 饱和占比 | 执行器够不够用 |
| 积分均值 / 限幅% | `velocity_integral` 统计 | **零点准不准** |

**`velMean` 必须带符号**——绝对值会把"来回摆"和"单向跑"混为一谈，这两者的对策完全相反。

### 4.4 三个自制的诊断脚本

| 脚本 | 作用 | 解决了什么问题 |
|---|---|---|
| `analyze_run.py` | 复现状态机 + 全套指标 | 主力工具 |
| `true_offset.py` | 从平衡数据反推真实平衡点 | 让 offset 标定从"扫参数"变成"一次测量" |
| `breakaway.py` | 测负载下的静摩擦突破电压 | 定位 stick-slip |
| `jerk_trace.py` | 打印极值时刻前后 2 秒的原始逐点轨迹 | **聚合统计看不出的问题** |

**`jerk_trace.py` 的价值要特别强调**：第 5.7 节那个 stick-slip 问题，
在任何聚合统计里都是隐形的，只有把原始逐点数据打出来才看得见。

> **教训：当聚合指标解释不了现象时，一定要去看原始波形。**

### 4.5 一个统计陷阱（我自己踩了）

第一次测静摩擦，我的判据是"轮子停着时给了 PWM，多久后开始转"，结论是
"10~20 PWM 就有 98% 能起步，静摩擦不是瓶颈"。**这个结论是错的。**

错在样本里混进了大量**PWM 正在上升**的时刻：记录的是"起步瞬间 PWM=15"，
但实际让它起步的是紧接着的 PWM=80。修正方法是加一个"指令已稳定"的过滤：

```python
# 指令必须与 100ms 前的值相差不超过 15 PWM，排除正在爬升的样本
lag = 10   # 编码器 100Hz，10 个样本 = 100ms
held = np.zeros(len(p), dtype=bool)
held[lag:] = np.abs(p[lag:] - p[:-lag]) < 15.0
```

加了过滤后，真实结论完全反转：突破电压在 **65~80 PWM** 量级。

> **教训：测阈值时必须排除瞬态样本，否则会系统性低估阈值。**

### 4.6 让一次录包包含几十次尝试

```python
self.declare_parameter('latch_on_fall', True)
```

默认摔倒后锁存，必须重启控制器才能再接管——调参时这非常低效。
调试期设成 `false`，摔了以后人扶正就自动重新接管，**一个 200 秒的录包能装下几十次尝试**，
统计意义强得多。

（无人值守运行时应该改回 `true`，避免一次摔倒后反复自动上电。）

## 5. 实战全过程 A1 → A11

### 5.0 起点状态

接手时的已知条件（来自 `docs/04_balance_tuning_pause_2026-07-24.md`）：

```
pitch_offset_deg = 7.20    (静态标定，std 0.11°，2374 采样)
kp = 70, kd = 5
motor_output_sign = 1.0    (已实测确认，不要翻)
最后一次测试：轮速冲到 +271 ticks/s 被安全锁存切断
```

### 5.1 A1：确认失败模式 —— 不是角度环的问题

**改动**：启用 `kd_wheel = 0.3`（轮速直接阻尼），`max_tilt` 5→12，`latch_on_fall` 关闭。

**结果**：

```
29 段接管，退出原因 100% 是 WHEEL，0 次 TILT
最好 7.76s，err 全程 [-1.72, +2.54]°
轮速末值稳定 ±430 ticks/s
```

**结论**：`kd_wheel` 完全没用，而且方向本来就是错的。

```python
wheel_damping = -kd_wheel * self.wheel_velocity   # v>0 时减小前进PWM = 直接刹车
u += wheel_damping
```

这正是第 3.1 节说的"错误答案"——直接刹车会让车身更前倾，角度环立刻反向加油门对抗。
**`kd_wheel` 是个结构性错误的工具，永久置 0。**

真正的收获是失败模式的确诊：**0 次 TILT 说明角度环从来就不是问题**，
前面所有对 kp/kd 的调整都调错了地方。

### 5.2 A2：符号修正 —— 从 7 秒到 367 秒

**改动**（单变量）：

```
kp_v: 0 → -0.005              # 符号见第 3.2 节推导
kd_wheel: 0.3 → 0             # 关掉错误的工具
velocity_filter_alpha: 0.3 → 0.06
max_offset_trim_deg: 4.0
```

**关于 `velocity_filter_alpha`**：一阶低通的截止频率 `fc ≈ α·fs/(2π)`。
编码器 100 Hz 时，α=0.3 → fc ≈ 4.8 Hz，**比角度内环还快**。
串级控制要求外环带宽远低于内环（一般 5~10 倍），否则两环互相打架。
降到 0.06 → fc ≈ 0.95 Hz，拉开了。

**结果**：

```
最长段 367 秒（此前最好 7.8 秒）
但 turnAvg = +78 → 原地转圈
```

**跑飞问题一次性解决**。这一轮证明了：前面几天的困境不是"参数没调好"，
而是**一个符号错误**。

### 5.3 A3：偏航同步 —— 差模控制

**现象**：能站很久，但原地转圈。`turnAvg` 长期 +78~+100（左轮持续比右轮快）。

**符号推导**：
- `turn = left_v - right_v`，turn > 0 表示左轮快
- 要纠正，需要**减小左轮、增大右轮**
- 由 `left = u - sync`、`right = u + sync`，减小左 / 增大右 ⇒ **sync 增大**
- `sync = wheel_sync_kp · turn`，turn > 0 时要 sync > 0 ⇒ **`wheel_sync_kp` 取正**

**改动**：`wheel_sync_kp = 0.25`，`max_wheel_sync_pwm = 60`，`max_wheel_velocity` 400→600。

**结果**：

```
turnAvg:  +78  →  +1 / -0 / -3      系统性偏航偏置归零
最长段 209.7s
但 velMean = -31 ticks/s → 慢速单向漂移
```

**为什么偏航环不干扰平衡环**：差模是等量反向叠加的（一个 -sync 一个 +sync），
左右轮 PWM 之和不变，即平均前后扭矩不变。**共模与差模天然解耦。**

### 5.4 A4：位置积分 —— 消灭稳态漂移

**现象**：`velMean = -31 ticks/s` 稳定的单向慢走，刹不住。

**原理**：纯 P 速度环存在**固有稳态误差**。设真实平衡点与配置的 offset 差 δ，
则稳态时必须有 `kp_v · v_ss = δ`，即 `v_ss = δ / kp_v ≠ 0`。
P 项在数学上不可能把速度归零——**必须引入积分项**。

实测吻合：`-0.005 × (-31) = +0.155°`，正好就是那个平衡点偏差。

**改动**：`ki_v = -0.0015`（符号与 kp_v 同号），`wheel_sync_kp` 0.25→0.4。

**幅值怎么定**：希望 v = -31 持续约 3.5 秒能积出所需的 0.155° 修正：

```
integral ≈ -31 × 3.5 = -108.5
ki_v = 0.155 / 108.5 ≈ 0.0014  →  取 -0.0015
```

安全性检查：`velocity_integral` 硬钳在 ±500，所以积分项贡献封顶
`0.0015 × 500 = 0.75°`，跑不飞。

**结果**：

```
velMean:  -31  →  +5 / -8       漂移消灭
errRMS 0.56°，最长段 114.7s
新现象：位置以 8.8 秒周期来回摆（用户描述："后退一段刹住，前进一段刹住"）
```

### 5.5 A5：位置环刚度 —— 用二阶系统理论定方向

**现象**：8.8 秒周期的位置来回摆，位置峰峰值 3.6 圈。

**先判断是不是线性欠阻尼**（决定了该加阻尼还是加刚度）：

```
观测周期 8.8s  →  ω_n ≈ 2π/8.8 ≈ 0.785 rad/s
由 ω_n² = -K'·ki_v  →  K' = 0.616 / 0.0015 ≈ 411
由 2ζω_n = -K'·kp_v  →  ζ = (411 × 0.005) / (2 × 0.785) ≈ 1.31
```

**ζ = 1.31 是过阻尼**。过阻尼的线性二阶系统**不会振荡**。
所以这个 8 秒摆动不是 PID 参数问题，另有原因；
同时也意味着**阻尼有富余，可以拿来换刚度**。

两个嫌疑：静摩擦极限环 / 积分限幅。查数据：

```
velocity_integral 撞 ±500 限幅：7.3% 样本，|I|>400：13.6%
```

积分确实在顶天花板——摆到极端位置时回复力被削顶、不再随位移增长，于是过冲。

**改动**：`ki_v` -0.0015 → **-0.003**（刚度翻倍），`kp_v` -0.005 → **-0.006**（补阻尼）。

预测：`ω_n ∝ √ki_v` → 周期 8.8 / √2 ≈ 6.2s；`ζ ∝ kp_v/√ki_v` → 1.31 → 1.14。

**结果**（预测基本命中）：

```
周期     8.8s  →  5.16s
posSD    0.84  →  0.37 圈
posPP    3.61  →  1.42 圈
errRMS   0.56  →  0.51°
最长段   114.7 → 134.1s
```

### 5.6 A6：零点精修 —— 从"扫参数"到"一次测量"

**现象**：刚度加倍后，`|I|>400` 的占比反而从 13.6% 涨到 **31.6%**，积分长期贴着天花板。

**推理**：稳态时速度为零，`trim = ki_v · I`。积分被长期顶住，说明它在
**补偿一个固定的直流偏差**——也就是 `pitch_offset_deg` 本身偏了，白白吃掉积分行程。

**怎么算出真实零点**（这是本项目最有价值的一个技巧）：

> **当车在平衡且长时间平均轮速为零时，车身的平均 pitch 就是真实机械平衡点。**

理由：平均轮速为零 ⇒ 长期没有净加速度 ⇒ 车身平均姿态必然就是重力力矩为零的姿态。

```python
# true_offset.py 的核心：直接取长段的平均 pitch
mean_pitch = pitch[engaged_and_settled].mean()
```

两轮独立数据高度一致：

```
tuneA4 平均 pitch = 7.528°
tuneA5 平均 pitch = 7.554°     ← 差 0.03°
```

而用外环 trim 反推的结果是不可信的（A4 给 7.46°，A5 给 8.21°，差 0.75°），
因为积分被限幅削过。**平均 pitch 法才是可靠的那个。**

**改动**：`pitch_offset_deg` 7.20 → **7.53**，同时 `ki_v` → -0.005，`kp_v` → -0.008。

**结果**：

```
积分均值:   -322  →  -49        不再长期补偿零点
积分限幅:   8.5%  →  0.0%       完全消失
errRMS      0.51  →  0.37°
posSD       0.37  →  0.25 圈
接管占比    153.4s / 155s（仅 2 段）
```

> **这一条对面试特别有说服力**：offset 这个参数在此前的会话里被反复试错扫描、
> 耗费了大量时间；用这个方法，一次录包就定死了，而且有独立的验证判据（积分均值→0、限幅→0%）。

### 5.7 A7：静摩擦补偿的尝试与失败

**现象**：偶尔一次向前"抽动"。用 `jerk_trace.py` 打出原始轨迹：

```
 t_rel   pitch    err    rate    pwm    vel
 -1.67    7.53   0.00   -0.7    -45      0   ← 持续给 -45 PWM，轮子纹丝不动
 -1.40    7.48  -0.05    0.1    -50      0
 -1.08    7.60   0.07    1.1    -34      0   ← 轮子卡住期间，车身开始自己前倾
 -0.82    8.32   0.79    6.0     40     26
 -0.35    9.06   1.53  -14.5    116    166   ← PWM 追到 116 才彻底挣脱
  0.05    5.46  -2.07  -26.8    -69    341   ← 挣脱后暴冲，车身反甩到 -2.07°
```

**教科书级的 stick-slip（黏滑）极限环**：
卡住 → 车身自己倾 → PWM 一路追高 → 突然挣脱 → 暴冲过冲。

用 `breakaway.py`（含 4.5 节的"指令已稳定"过滤）测负载下的突破电压：

```
        FWD 移动率   BWD 移动率
25-35     60.5%       63.6%
45-55     50.3%       47.9%     ← 一半概率推不动
65-80     80.4%       84.9%
```

平衡时 `|u|` 大部分时间落在 25~55 这个"掷硬币"区间。

**改动**：启用 `deadband_output_ramp` 通路：

```python
effort_scale = min(1.0, abs(u) / deadband_output_ramp)          # 按PID输出大小给助力
speed_scale  = max(0.0, 1.0 - abs(wheel_velocity) / deadband_velocity)  # 转起来后褪去
u += deadband_fwd * effort_scale * speed_scale
```

参数：`deadband_pwm_fwd/bwd=35`，`output_ramp=20`，`velocity_threshold=80`，
`deadband_err_deg=1.0 → 0.05`（默认要等车身倾过 1° 才补偿，那正是要避免的）。

**结果：全线退步，偏航退得最狠。**

```
errRMS   0.37 → 1.10°
turnAvg  -0   → +93
|turn|max 235 → 1088
```

**机理分析**（详见第 6.5 节）：助力只加在共模 `u` 上，而左右轮突破电压不同。
原来两轮大多**一起卡住**（对称，不产生偏航）；加了助力后共模被抬进
"一个挣脱了另一个还卡着"的区间，直接变成大差速。

### 5.8 A8：回退失败 —— 真凶是硬件

把 A7 的死区参数全部清零，**完全回到 A6 配置**。结果不但没恢复，反而更差：

```

三个独立信号同时指向硬件：

```

**一个松动的紧固件能同时解释这三条**：姿态基准改变（零点漂移）+

之前出现过"IMU 螺丝松动掉了"。

紧固硬件后，A9 用**完全相同的 A6 参数**跑出了比 A6 更好的结果——

## 6. 踩过的六个坑

### 6.1 符号错误（`kp_v`）—— 最贵的一个

**表现**：速度环怎么调都没用，加大增益只会让跑飞更快。
**根因**：把 `kp_v` 当成普通的负反馈增益取了正值，忽略了非最小相位特性。
**代价**：数天。
**教训**：**欠驱动系统的外环符号必须推导，不能靠直觉。**
推荐两条路交叉验证：物理过程推演 + 特征方程系数判稳。

### 6.2 工具选错（`kd_wheel`）

```python
wheel_damping = -kd_wheel * self.wheel_velocity   # 看起来很合理的"轮速阻尼"
```

**表现**：加了没用，加大了更糟。
**根因**：这是直接刹车，会让车身更前倾，与平衡环正面对抗。
**教训**：**在欠驱动系统里，不能对被控量直接施加阻尼，必须经由内环。**
`kd_wheel` 这个参数本身就是个设计错误。

### 6.3 外环带宽过高（`velocity_filter_alpha`）

**表现**：外环与内环互相打架。
**根因**：一阶低通 `fc ≈ α·fs/(2π)`。α=0.3 @ 100Hz → 4.8 Hz，比内环还快。
**教训**：**串级控制中外环带宽应为内环的 1/5 ~ 1/10。**
换硬件/改采样率后，同一个 α 值对应的截止频率会变——
本项目 IMU 从 303 Hz 变成 147 Hz 后，所有滤波系数的实际含义都变了一半。

### 6.4 统计陷阱（静摩擦阈值）

**表现**：第一次测得突破电压 10~20 PWM，据此判断"静摩擦不是问题"，结论完全错误。
**根因**：样本混入了 PWM 正在爬升的瞬态。
**教训**：见 4.5 节。**测阈值必须排除瞬态样本。**

### 6.5 共模 vs 差模（摩擦补偿）

**表现**：静摩擦补偿"生效了"（高 PWM 区移动率 92.9%→97.0%）却让整体变糟，偏航暴涨。
**根因**：

```
补偿加在共模 u 上  →  left = (u + 助力) - sync
                      right = (u + 助力) + sync
```

左右轮突破电压不同。**没有助力时两轮倾向于一起卡住（对称，无偏航）**；
加了助力后被抬进"一个挣脱一个还卡着"的区间，产生大差速。
而偏航环无力纠正——它自己那点差速修正量同样推不动一个卡住的轮子。

**教训**：**摩擦补偿必须作用在差速拆分之后的每个轮子上，不能加在共模上。**
代码里现有的 `deadband_dither_hz` 通路有同样的结构缺陷。

### 6.6 硬件故障伪装成调参问题 —— 最容易浪费时间的一个

**表现**：A7 改了参数变差 → 判断是参数的锅 → A8 回退 → **没恢复，反而更差**。
**根因**：一个松动的紧固件。它同时造成零点漂移、左右不对称、整体失效。
**当时的错误**：把 A7 的退步归因于刚改的摩擦补偿。那个归因是错的——
撤销后偏航仍在，说明真凶另有其人，A7 的退步很可能也是硬件。

**判据（写死记住）**：

> **多个互不相关的指标同时退步，且回退参数无法恢复 → 停止调参，去查硬件。
> 不要归因于最近一次参数改动。**

三个典型信号：
1. 零点（平衡时平均 pitch）整体漂移
2. 出现新的左右不对称（turnAvg 突然有偏置）
3. 退步幅度远超参数改动能解释的量级

**预防**：紧固件上螺纹胶；每次长时间摔打测试后检查一遍；
把"平衡时平均 pitch"作为常规健康指标监控，它是最早的预警信号。

## 7. 遗留问题与后续思路

### 7.1 静摩擦补偿未实现（中等优先级）

**现状**：负载下突破电压 65~80 PWM，而控制器大部分时间工作在 25~55 PWM 区间，
即"一半概率推不动"的区域。硬件紧固后 stick-slip 大幅缓解（velMax 606→239），
但机理仍在。

**思路 A（推荐）：把补偿移到差速拆分之后**

在 `serial_bridge` 里、或在控制器中先算出左右轮 PWM 再分别补偿：

```python
left_raw  = u - sync
right_raw = u + sync
left_pwm  = left_raw  + copysign(deadband_left,  left_raw)  * scale(left_raw)
right_pwm = right_raw + copysign(deadband_right, right_raw) * scale(right_raw)
```

这样每个轮子按自己的突破电压补偿，不会互相干扰产生偏航。
`deadband_left/right` 需要**分别标定**（用 `breakaway.py` 分左右轮统计，
需要先把 `/wheel/encoders` 的左右分量单独存下来）。

**思路 B：抖动注入（dither）**

代码里已有 `deadband_dither_hz` 的 sigma-delta 实现——用满幅脉冲的占空比
去等效小扭矩，避免持续偏置。但它同样加在共模上，**必须先按思路 A 移到差模之后**。

**思路 C：硬件层面**

换更好的减速箱 / 加润滑 / 换轮胎材质。静摩擦本质是机械问题，
控制补偿只是治标。

### 7.2 `velocity_integral` 限幅是硬编码（低优先级，容易改）

```python
self.velocity_integral = max(-500.0, min(500.0, self.velocity_integral))
```

±500 ticks ≈ 1.8 圈。这个值在 A5 阶段是真实的性能瓶颈（限幅占 7.3%）。
应该提成 ROS 参数，比如 `max_velocity_integral`，方便按场地大小调整。

### 7.3 偏航只有 P 控制（低优先级）

`wheel_sync_kp` 是纯比例，能压掉系统性偏置（turnAvg +78 → +1），
但残余瞬时摆动仍有峰值 200~600。若要更严格的航向保持，可以：

- 加偏航积分项，或
- 引入 IMU 的 yaw 角做绝对航向反馈（现在只用了差模轮速，是相对量，
  会随时间累积航向漂移——**车能不转圈，但长期朝向会慢慢偏**）

### 7.4 `pitch_rate` 用差分而非陀螺仪原始值（中等优先级）

```python
pitch_rate = (pitch - self.last_pitch) / pitch_dt
```

D 项的角速度是对 pitch 做差分得到的，**差分会放大噪声**，所以才需要
`pitch_rate_filter_alpha` 低通，而低通又引入相位滞后。

IMU 本身就输出 `angular_velocity.y`（陀螺仪原始角速度），信噪比高得多。
当初改用差分是为了规避"IMU 安装轴与 Euler 轴不一致"的问题
（见代码注释）。正确做法是**做一次轴对齐标定**，然后直接用陀螺仪值，
可以同时降噪声和降滞后，为提高 kd 腾出空间。

> **⚠️ 2026-07-27 更正：以上这段在本机上被实测推翻，不要照做。**
>
> 轴对齐标定已用离线数据完成：`angular_velocity.y` 确实对应 pitch 且符号为正
> （r = +0.835，另两轴 |r| < 0.07）。**但陀螺那一路是滞后的** ——
> 互相关显示四元数推出的 pitch 角速度**超前陀螺 18 ms**
> （谱分析在 6~9 Hz 给出 +50.6 度，两法吻合）。
> 换用陀螺会在 7~9 Hz 自激点上再叠 50 度相位滞后，只会更糟。
> 详见 `docs/07_遥控与录制_2026-07-26.md` 第 11 节 ③。

### 7.5 IMU 采样率异常下降（待查）

文档 04 记录 IMU 为 303 Hz，本次实测为 **147~152 Hz**，掉了一半，原因不明。
可能是驱动配置、USB 带宽或 IMU 内部输出速率设置。

**影响**：所有一阶滤波系数的实际截止频率都减半了
（`fc ≈ α·fs/(2π)`）。当前参数是在 147 Hz 下调的，
如果哪天 IMU 恢复到 303 Hz，`pitch_rate_filter_alpha` 和
`velocity_filter_alpha` 需要相应减半才能保持等效。

### 7.6 尚未实现运动控制（下一阶段的主要工作）

现在外环的速度目标隐含为 0，只会原地站立。要让它能走：

```python
# 现在
offset_trim = kp_v * self.wheel_velocity + ki_v * self.velocity_integral

# 改成
vel_err = self.wheel_velocity - target_velocity
offset_trim = kp_v * vel_err + ki_v * self.velocity_integral
# 注意：给了非零速度目标后，位置积分的含义变成"相对于期望轨迹的位置误差"，
# 需要同步处理，否则积分会持续累积
```

转向类似：给偏航环一个 `target_turn_velocity` 而不是恒定 0。

再往上才是导航层（里程计、路径跟踪）。注意目前 `ticks_per_rev = 277.5`
是手转粗标的，做里程计前需要精标定。

## 8. 面试准备

### 8.1 一句话项目描述

> 基于 ROS2 的两轮自平衡机器人，采用角度环 / 速度环 / 位置环 / 偏航环的四环串级 PID 控制，
> 通过 rosbag 数据驱动的方式完成参数整定，实现单次连续平衡超过 228 秒，
> 车身角度控制在 ±1° 以内，原地位置保持在 1/4 轮周以内。

### 8.2 高频问题与答法

**Q：为什么要用串级控制？只调一个角度 PID 不行吗？**

A：不行，而且我有实测数据。只有角度环时，车身确实能稳定在 ±2.5° 以内，
但整车会以 430 ticks/s 持续加速跑掉。原因是角度环的目标只是"让 pitch 等于设定值"，
只要设定值有微小偏差，车身就会稳定保持一个微小倾角，而持续倾斜的平衡车会持续加速，
角度环对此毫无察觉——它的误差是零。这是欠驱动系统的本质：
一个执行器要控制两个自由度，必须用串级结构分层处理。

**Q：平衡车的速度环增益为什么是负的？**

A：因为它是非最小相位系统。要让前进的车减速，不能直接刹车——
那样车身会因惯性更加前倾，角度环会立刻加大前进油门去救它，刹车动作被完全抵消。
正确做法是先加大前进油门，把轮子送到重心前面，车身被"抽"得后仰，
然后角度环为了追这个后仰的重心，自己会输出反向 PWM 完成减速。
符号可以严格推导：v>0 要减速 → 需要 u 更正 → err 更正 → 目标角更小 →
trim 为负 → kp_v 为负。也可以从特征方程 `s² - K'·kp_v·s - K'·ki_v = 0`
的系数判稳得到同样结论。这个符号我们项目早期搞反了，导致速度环是正反馈，
浪费了好几天。

**Q：你是怎么调参的？试凑吗？**

A：不是，是数据驱动。流程是：`ros2 param set` 设参数 → `ros2 bag record` 录包
→ 拉回本地离线分析 → 从指标推下一组参数。
关键在于离线分析时**精确复现控制器的状态机**——因为知道全部参数，
可以重建每一段"接管"的起止和退出原因。这个"退出原因"这一列价值极高：
如果全是倾角超限，说明角度环兜不住；如果全是轮速超限，说明角度环没问题，
是速度失控。我们第一轮的数据是 29 段全部轮速超限、0 次倾角超限，
直接就把排查方向从角度环转到了速度环，避免了继续在错误的地方调 kp/kd。

**Q：举一个你用理论指导调参的例子。**

A：位置环出现了 8.8 秒周期的来回摆。我先判断这是不是线性欠阻尼：
由观测周期反推 ω_n ≈ 0.785 rad/s，再由 `ω_n² = -K'·ki_v` 反推系统增益 K' ≈ 411，
最后算出阻尼比 ζ ≈ 1.31。**过阻尼系统不会振荡**，所以这个摆动不是 PID 参数问题，
另有原因（后来查出是积分限幅）；同时也说明阻尼有富余，可以拿来换刚度。
于是把 ki_v 加倍、kp_v 小幅跟进，预测周期降到约 6.2 秒——
实测 5.16 秒，位置摆幅从 3.6 圈降到 1.4 圈。用理论先做定量预测再验证，
比盲目试参数效率高一个数量级。

**Q：机械零点是怎么标定的？**

A：一开始是静态标定——扶正了采样取平均，但这个方法很脆弱，
人手扶的姿态和真实平衡点未必一致，之前为此反复扫描浪费了大量时间。
后来我用了一个更好的方法：**当车在自主平衡、且长时间平均轮速为零时，
车身的平均 pitch 就是真实机械平衡点**。因为平均轮速为零意味着长期没有净加速度，
车身平均姿态必然就是重力力矩为零的姿态。
两轮独立数据给出 7.528° 和 7.554°，一致到 0.03°。
更重要的是这个方法**自带验证判据**：零点对了以后，速度环积分的均值应该趋近于零、
且不再撞限幅——实测从 -322 降到 -49，限幅占比从 8.5% 降到 0%。

**Q：讲一个你调试中判断失误的例子。**

A：有一轮我加了静摩擦补偿，结果所有指标都变差、偏航特别严重，
我第一反应是补偿的锅，就把它撤销了。**结果撤销后没恢复，反而更差。**
这说明我的归因是错的。回头看三个信号：平衡时的平均 pitch 整体漂移了 0.5°、
突然出现左右不对称、退步幅度远超参数改动能解释的量级——
这三条同时出现只能是机械问题，最后查出是紧固件松动。
这件事给我的教训是：**当多个互不相关的指标同时退步、
且回退参数无法恢复时，应该立刻停止调参去查硬件，而不是归因于最近一次改动。**
后来我把这条写进了项目文档作为判据。

**Q：还有什么没做好的？**

A：主要三点。第一，静摩擦补偿还没做对——现在的实现加在共模上，
会导致一个轮子挣脱另一个还卡着，产生偏航，正确做法是移到差速拆分之后按轮补偿。
第二，D 项的角速度是对 pitch 做差分得到的，噪声大、需要低通、又引入滞后；
应该做一次轴对齐标定后直接用陀螺仪原始角速度。
第三，偏航只有比例控制，用的是编码器差模这个相对量，
长期朝向会缓慢漂移，需要引入 IMU 的 yaw 做绝对反馈。
